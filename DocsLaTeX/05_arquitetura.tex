\section{Introdução e Propósito}
Este documento descreve a arquitetura atual do sistema Seeban, com foco nas decisões técnicas adotadas para implementar um software Kanban com autenticação, persistência relacional, interface web e cálculo de métricas operacionais.
O objetivo é registrar os elementos arquiteturalmente significativos que orientam evolução, manutenção e validação técnica do projeto.

\section{Metas Arquiteturais e Filosofia}
A arquitetura foi concebida para atender aos requisitos funcionais de gestão Kanban (projetos, quadros, raias, cartões, movimentação e métricas) com separação clara de responsabilidades.
Para isso, foi adotado o padrão Model-View-Controller (MVC) combinado com uma camada explícita de repositórios para isolamento da persistência em MySQL.

\begin{itemize}
    \item \textbf{Objetivos da Arquitetura:}
    \begin{itemize}
        \item Separar interface, regras de negócio e acesso a dados;
        \item Facilitar evolução incremental por funcionalidade;
        \item Reduzir acoplamento entre front-end (Streamlit) e SQL;
        \item Melhorar testabilidade de regras em controllers/repositories;
        \item Garantir consistência de dados em operações transacionais.
    \end{itemize}
\end{itemize}

\section{Suposições e Dependências}
\begin{itemize}
    \item \textbf{Suposições:}
    \begin{itemize}
        \item O servidor MySQL está disponível e acessível pela aplicação;
        \item O schema do banco foi criado a partir do script do projeto;
        \item O usuário final acessa a aplicação via navegador compatível com Streamlit;
        \item A equipe opera com fluxo incremental de entrega de funcionalidades.
    \end{itemize}
\end{itemize}

\begin{itemize}
    \item \textbf{Dependências:}
    \begin{itemize}
        \item Python 3;
        \item Streamlit;
        \item mysql-connector-python;
        \item Banco de dados MySQL.
    \end{itemize}
\end{itemize}

\section{Requisitos Significativos para a Arquitetura}
Os requisitos que mais impactam a arquitetura são:

\textbf{Funcionais:}
\begin{itemize}
    \item Autenticação de usuário com validação em banco relacional;
    \item CRUD de projeto, quadro, raia e cartão;
    \item Movimentação de cartão entre colunas e raias;
    \item Cálculo de métricas (Cycle Time, Lead Time, Throughput, WIP);
    \item Compartilhamento de projeto por convite de integrantes.
\end{itemize}

\textbf{Não funcionais:}
\begin{itemize}
    \item Usabilidade: navegação orientada por páginas e menu lateral;
    \item Disponibilidade: operação contínua em arquitetura web simples;
    \item Tempo de resposta: consultas e atualizações diretas em SQL com escopo reduzido;
    \item Manutenibilidade: organização modular por camadas.
\end{itemize}

\section{Mecanismos e Abstrações Arquiteturais}
\begin{itemize}
    \item \textbf{Mecanismo de Persistência:} MySQL com mysql-connector-python, conexão centralizada em \texttt{database/connection.py} e operações encapsuladas em repositories.
    \item \textbf{Mecanismo de Autenticação:} validação de credenciais via \texttt{auth\_controller} e \texttt{user\_repository} consultando a tabela \texttt{usuarios}.
    \item \textbf{Mecanismo de Interface Gráfica:} páginas Streamlit (\texttt{login\_page}, \texttt{project\_page}, \texttt{board\_page}) e navegação por estado de sessão.
    \item \textbf{Mecanismo de Regras de Negócio:} controllers para orquestrar validações, transições de estado e mensagens de domínio.
    \item \textbf{Mecanismo de Manipulação Kanban:} criação automática de colunas padrão (\texttt{A\_FAZER}, \texttt{FAZENDO}, \texttt{FEITO}), raia principal, CRUD de cartões/raias e movimentação com histórico.
    \item \textbf{Abstrações Chave:} Usuário, Projeto, Quadro, Coluna, Raia, Cartão, Histórico de Movimentação.
\end{itemize}

\section{Framework Arquitetural}
O sistema adota o padrão Model-View-Controller (MVC) com apoio da camada Repository:

\begin{itemize}
    \item \textbf{View:} responsável por renderizar páginas e componentes de interação no Streamlit;
    \item \textbf{Controller:} centraliza regras de negócio, validações e coordenação de casos de uso;
    \item \textbf{Model:} representa entidades do domínio em classes simples;
    \item \textbf{Repository:} implementa acesso a dados e transações SQL.
\end{itemize}

\begin{itemize}
    \item \textbf{Elementos:}
    \begin{itemize}
        \item \texttt{views/login\_page.py}: autenticação e cadastro;
        \item \texttt{views/project\_page.py}: gestão de projetos;
        \item \texttt{views/board\_page.py}: gestão de quadros, raias, cards e métricas;
        \item \texttt{controllers/*}: lógica de autenticação, projetos, quadros, raias e cards;
        \item \texttt{repositories/*}: CRUD e consultas SQL por entidade;
        \item \texttt{models/*}: mapeamento das entidades de domínio;
        \item \texttt{database/connection.py}: pool e configuração de conexão.
    \end{itemize}
    \item \textbf{Impacto de Ferramentas (Frameworks e Bibliotecas):}
    \begin{itemize}
        \item Streamlit acelera construção de interface e prototipação;
        \item MySQL garante consistência relacional para operações de Kanban;
        \item mysql-connector-python permite integração direta com SQL e transações.
    \end{itemize}
\end{itemize}

\section{Visões da Arquitetura}
\subsection{Visão Lógica}
A visão lógica está organizada por pacotes:

\begin{verbatim}
seeban/
|-- app.py
|-- views/
|   |-- login_page.py
|   |-- project_page.py
|   `-- board_page.py
|-- controllers/
|   |-- auth_controller.py
|   |-- project_controller.py
|   |-- board_controller.py
|   |-- lane_controller.py
|   `-- card_controller.py
|-- models/
|   |-- user.py
|   |-- project.py
|   |-- board.py
|   |-- lane.py
|   |-- column.py
|   |-- card.py
|   `-- movement_history.py
|-- repositories/
|   |-- user_repository.py
|   |-- project_repository.py
|   |-- board_repository.py
|   |-- lane_repository.py
|   `-- card_repository.py
`-- database/
    `-- connection.py
\end{verbatim}

Fluxo típico: \texttt{View} recebe evento $\rightarrow$ \texttt{Controller} aplica regra $\rightarrow$ \texttt{Repository} persiste/consulta no MySQL $\rightarrow$ resultado retorna para a \texttt{View}.

\subsection{Visão Operacional (Implantação)}
Implantação simplificada em três blocos:
\begin{itemize}
    \item Processo da aplicação Streamlit (camada web + regra de negócio);
    \item Banco MySQL (persistência relacional);
    \item Cliente web (navegador do usuário).
\end{itemize}
O estado de navegação e sessão do usuário é mantido via \texttt{st.session\_state} no processo da aplicação.

\subsection{Visão de Casos de Uso (Histórias)}
Casos de uso arquiteturalmente relevantes já implementados:
\begin{itemize}
    \item Autenticar e cadastrar usuário;
    \item Criar, alterar, excluir e listar projetos;
    \item Convidar usuário para projeto;
    \item Criar, alterar, excluir e listar quadros do projeto;
    \item Criar, atualizar, excluir e ler raias;
    \item Criar, atualizar, excluir, ler e mover cartões;
    \item Calcular e exibir métricas de fluxo (Cycle Time, Lead Time, Throughput e WIP).
\end{itemize}
